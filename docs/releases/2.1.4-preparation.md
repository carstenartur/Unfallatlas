## Publication blockers established from evidence

### 1. Dependency security gate is not green

The existing [npm Security Audit Evidence run 41206299228](https://github.com/carstenartur/Unfallatlas/actions/runs/41206299228)
audited immutable original base
`cfbfe922917434b768a9eccf6678bc747885f52c` with pinned npm 11.19.1 on
2026-10-31. The log reported:

- production dependencies: **1 high, 1 critical**;
- full installation: **3 high, 1 critical**.

The same High/Critical counts remained on
[security PR #722](https://github.com/carstenartur/Unfallatlas/pull/722),
head `43f4616548f75adb57f0a8b198ec15c77bcc9d99`, and its enforcement step
failed with exit code 2. Updating `ip-address` alone is therefore not evidence
that the release security gate has passed. The recorded source still overrides
`ip-address` to 10.7.2; the lockfile includes it through `express-rate-limit`.

Resolve the actual findings in the existing dependency work and require a fresh
passing audit on the final candidate. Do not suppress audit enforcement or infer
exploitability solely from an audit count. The run also exceeded the GitHub step
summary size limit after the substantive gate failure; its evidence artifact was
nevertheless uploaded successfully.

### 2. Microsoft Word evidence is missing from the candidate

At this source, `docs/release-evidence/` contains only
`word-compatibility.example.json`, with placeholders and all checks false.
It is not a completed receipt. The
[Word compatibility contract](../word-compatibility-release-check.md) requires a
recent, fingerprint-matching receipt and a passing dedicated workflow.

Generate the exact candidate DOCX, open/save/reopen it in Microsoft Word, complete
the documented checks, and validate the receipt on the final source. LibreOffice,
OOXML inspection and browser previews cannot substitute for that evidence.

### 3. Full release acceptance has not yet run for this candidate

The preparation PR triggers the existing `Tests` workflow, including
`extended-qa`, because that job is enabled for pull requests. Its command is:

```bash
mvn -B -ntp clean verify \
  -Pe2e,system-it,location-brief-golden,context-data-e2e \
  -Dcontext.city=Hannover '-Dfailsafe.includes=**/*IT.java'
```

Inspect the resulting PR checks. Their completion is separate from the full
release dry run below, which also includes publication and document-render
profiles. A queued, running or skipped job is not a passed gate.

## Exact non-publishing release rehearsal

After reviewed preparation and any necessary fixes have reached authoritative
`main`, run **Release Workflow** (`.github/workflows/deploy-release.yml`) with:

| Input | Value |
|---|---|
| `next_development_version` | `2.1.5-SNAPSHOT` |
| `next_version_increment` | `patch` |
| `dry_run` | **`true`** |

The workflow always checks out `main`; selecting a preparation branch in the
dispatch UI does not qualify unmerged contents. Its actual Java setup is JDK 25
(the existing step label still says Java 21), and Maven installs the pinned Node
24.17.0/npm 11.19.1 toolchain.

The authoritative acceptance command on the locally created release commit is:

```bash
PLAYWRIGHT_INSTALL_SYSTEM_DEPS=1 mvn -B -ntp clean verify \
  -Prelease-site,pages,e2e,system-it,location-brief-golden,document-render \
  '-Dfailsafe.includes=**/*IT.java'
```

Keep the full Failsafe include: the Golden profile otherwise narrows the test
selection. Preserve all existing timeouts, security, media, licence and provenance
gates. Docker, Chromium/Firefox/WebKit, LibreOffice, Poppler and document fonts
must be available as provisioned by the workflow.

Review the `release-acceptance-evidence` and
`release-dry-run-candidate-2.1.4` artifacts. Bind approval to their exact source
and metadata state. Also finish the repository's
[manual operating-mode checklist](../release-checklist.md).

This preparation has not dispatched or passed that dry run and has created no
release tag, GitHub Release or container publication. Actual publication requires
a separate reviewed action after all applicable gates pass.
