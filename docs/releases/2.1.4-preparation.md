### Source-bound document QA added here

[Document release QA](../document-release-qa.md) generates a real production
numbered appendix from every published Bonn accident in a fixed test selection.
Native PDF, DOCX, CSV and GeoJSON share exact IDs, source fingerprints and map
receipts. Positioned rendered words independently reconstruct every table cell,
page-spanning header and visible map caption; extracted final images are compared
by decoded pixels. The controlled basemap is visibly synthetic and does not claim
live tile availability.

The implementation's complete render runner passed all five layout scenarios and
its unit gate (18 suites / 103 tests). Independent review then added actual local
file-read acquisition and positioned visible-caption checks. After integrating
current main and pdfmake 0.3.14, the three release-specific suites passed 15 tests
and the actual release case was rendered again on 2026-11-08:

## Acceptance still requiring evidence

### Microsoft Word

No actual Microsoft Word receipt has been recorded. The existing validator rejects
placeholder checks, wrong input fingerprints and evidence older than 30 days.
The Word input fingerprint now also binds the numbered-appendix exporter, map
fixture and release-case generator, so an older receipt cannot qualify changed
long-table output. Recompute it on the final candidate with:

```bash
node scripts/validate-word-compatibility-evidence.js --print-fingerprint
```

Use the final CI `rendered-document-evidence` artifact, including the ordinary
sample and `out/qa/release-document/appendix.docx`. Open, save, close and reopen
in desktop Microsoft Word, and record the actual Word/OS version, reviewer,
page counts, unbroken tables, undistorted maps, headings, hyperlinks and glyphs.
The matching source DOCX bytes and final candidate fingerprint must accompany
the receipt. LibreOffice conversion does not substitute for this observation.
See [Word compatibility](../word-compatibility-release-check.md).
